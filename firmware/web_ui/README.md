# Веб-интерфейс Sirokko

Веб-интерфейс на Svelte. Сборка объединяет страницу и библиотеку SHA-256 для OTA в один HTML-файл.

Из корня репозитория:

```sh
npm ci --prefix firmware/web_ui
npm run build --prefix firmware/web_ui
python3 firmware/tools/embed_web_ui.py
python3 firmware/tools/embed_web_ui.py --check
```

`npm run build` формирует `dist/index.html`, обновляет `THIRD_PARTY_NOTICES.txt` и проверяет самодостаточность страницы. `embed_web_ui.py` сжимает HTML и записывает `../main/web_ui_data.inc`; `--check` подтверждает совпадение встроенной страницы с результатом сборки.


Страницы `Control`, `Timer`, `Diagnostics`, `Settings`, `Heater`, `Wifi`, `Calibration`, `Regulation`, `Update` разделены по задачам. `App` хранит маршруты и черновики, `ControllerSession` — связь и подтверждение команд; `presentation.js` содержит общие правила отображения. Переходы используют hash и историю браузера. Интерфейс не определяет готовность отопителя по USB или наличию отдельных датчиков: разрешения и причины получает из `commands` ответа `/api/state`.

Команда считается применённой после соответствующего нового состояния, а не ответа `QUEUED`. При потере связи редактирование отключено, остановка активного нагрева остаётся доступной. Неизвестные показания не заменяются нулём. Черновики сохраняются между страницами и требуют обновления при изменении редактируемых данных другим клиентом.

Проверки логики браузера: `node --test firmware/web_ui/tests/*.test.mjs` из корня репозитория.

При переработке интерфейса использована методика [unslop](https://github.com/heydamir/unslop), Damir Sokolovsky (@heydamir), CC BY 4.0.

Коды протокола и маски ошибок не выводятся пользователю. Причины отказов, ошибки и события отображаются словами; неизвестный ответ получает сообщение по контексту действия.

Визуальная основа — круговая шкала и экраны процессов местной панели. По умолчанию тема следует системной, включая изменения во время работы. В настройках можно выбрать светлую или тёмную вручную; выбор сохраняется в браузере. Используется системный шрифт устройства, без загрузки шрифтов или других ресурсов из Интернета.

Температура и режим, таймер и плавность имеют независимые черновики. Сохранение на одной странице не применяет и не сбрасывает незавершённые правки на другой. Обратный отсчёт не создаёт конфликт редактирования, но изменение срока отключения другим клиентом требует загрузить актуальное значение.

Вкладка «Таймер» показывает отсчёт, позволяет выбрать длительность и отключить таймер без остановки нагрева. Плавность вынесена в «Настройки → Дополнительно». По умолчанию регулятор работает в пределах модели; ручные ползунки только снижают предел скорости, не повышая его. Возврат к автоматике снимает пользовательский предел, сохраняя ограничения модели. Числовых полей для плавности в веб-интерфейсе нет.

«Параметры отопителя» открываются из настроек, состояния и причины блокировки калибровки. `heater.js` переводит единицы формы в единицы протокола; ограничения поступают от ядра вместе с состоянием. Профиль имеет отдельный черновик. Смена исходных пределов доступна только при остановке, проверяется контроллером и сбрасывает прежнюю модель. Инициализация драйверов отображается отдельно от физического подключения экрана и кнопки, которое схема не определяет.
