# Веб-интерфейс прошивки

Production Svelte-интерфейс, перенесённый из принятого мобильного макета. Источник состояния — только `/api/state`; демонстрационный автомат в приложение не входит. Готовая автономная страница с локальными шрифтами и лицензиями сжимается и встраивается в `main/web_ui_data.inc`; ESP-IDF и устройство не требуют Node.js.

## Сборка из корня репозитория

Закреплены Node.js 26.7.0 и зависимости `package-lock.json`.

```sh
npm ci --prefix firmware/web_ui
npm run build --prefix firmware/web_ui
python3 firmware/tools/embed_web_ui.py
python3 firmware/tools/embed_web_ui.py --check
python3 firmware/tests/run_host_tests.py
python3 firmware/tests/run_host_tests.py --sanitize
```

Браузерные проверки:

```sh
cd firmware/web_ui
export PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers"
npx playwright install --with-deps chromium webkit
npm run test:browser
```

Тестовый сервер на loopback отдаёт **те же gzip-байты и CSP**, что production `page_handler`, экспортированные C++ host-тестом. Команды и динамические состояния в Playwright — явно синтетические сетевые сценарии. Отдельный сценарий использует фактический JSON сериализатора; ещё один проверяет SHA-256 при небезопасном HTTP origin без `crypto.subtle`. Это не эмуляция ESP32 и не физическое испытание AP.

## Контракт

- Единственный таймер отключения. В IDLE сохраняет интервал до выключения после ручного START; в активном сеансе меняет срок от сейчас. Ноль отменяет автоотключение. `ARM` и `CANCEL_ARM` публично не принимаются.
- Черновик привязан к снимку; challenge сверяется по `state_version` и `boot_id`. Backend повторно проверяет разрешение перед постановкой в очередь. Параметры целиком берутся из действующего снимка, а не из клиентского профиля по умолчанию.
- `QUEUED` не означает выполнение. Новый снимок должен соответствовать запросу; это наблюдение результата, а не отдельная квитанция о причинно связанном выполнении команды; через 5 с без подтверждения результат неизвестен. STOP идёт отдельно, не ждёт обычного разрешения.
- Ошибочный/устаревший сетевой снимок блокирует обычные команды; у датчиков отдельно проверяется `valid`/`fresh`. После reboot или потери авторизации старые черновики сбрасываются.
- OTA: `VERIFIED_ACTIVATION_QUEUED` означает только проверенную очередь. Ожидаемая версия приходит от проверенного образа. Наблюдение продолжается после повторного входа, сравнивает новый `boot_id` и версию; другая версия или timeout не объявляются успехом. Опрос приостанавливается на время тела OTA, чтобы не конкурировать за однопоточный HTTP server. Глобальный аварийный баннер виден на каждой странице и важнее успешного наблюдения версии. Физические reboot/rollback здесь не подтверждаются.

## Зависимости и ограничения

Svelte, локальные IBM Plex Sans, Tailwind/daisyUI; уведомления включены в HTML и `THIRD_PARTY_NOTICES.txt`. Встроен MIT js-sha256 0.11.1, без CDN. Полный `npm audit` выявляет две низкие записи, относящиеся к одной цепочке build-only `deepmerge` → Svelte Vite plugin, без доступного исправления; `npm audit --omit=dev` — без найденных уязвимостей. Конфигурация сборки доверенная локальная, сетевые данные контроллера не передаются в build-only deepmerge.
