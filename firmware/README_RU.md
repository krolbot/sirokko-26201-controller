# Прошивка контроллера Sirokko 262.01

Это ESP-IDF-проект управляющей платы на ESP32-S3-DevKitC-1-N8R8 v1.1. Он содержит независимое C++-ядро автомата, драйверы двух MAX31856 и DS18B20, локальный OLED/кнопочный пульт, USB-CLI для стенда, NVS-конфигурацию с явной приёмкой и журнал последних восьми аварий.

ВАЖНО: это DRAFT для сборки и стендовой проверки. Прошивка по умолчанию не содержит принятого режима горения и остаётся в LOCKOUT. Сборка `.bin`, host-тесты и наличие GPIO-контракта не разрешают огневую эксплуатацию. Внешние БП, 24-вольтовую автомобильную свечу и силовые исполнительные компоненты выбирает пользователь; токи нагрузок не должны проходить через логику ESP32.

## Что реализовано

- Состояния: `BOOT_SELF_TEST`, `WAIT_COOLDOWN`, `PREPURGE`, `PREHEAT`, `SPINUP`, `IGNITION_TRIAL`, `FLAME_CONFIRM`, `RUN_HIGH`, `RUN_LOW`, `POST_PURGE`, `LOCKOUT`.
- Два последовательных разрешения топлива: `FUEL_CMD` и `FUEL_PERMIT`.
- Fail-safe STOP, аппаратный `SAFETY_OK`, `ARM_READY`, `SW_TRIP` и heartbeat внешнего watchdog.
- RESET согласован с асинхронной DRAFT-02 защёлкой: при готовности к ручному сбросу `SW_TRIP` снимается до физического фронта; `SAFETY_OK` должен быть замечен во время удержания, а удержание при boot/аварии не создаёт самовзвод.
- Heartbeat формируется проходами основного автомата; валидатор учитывает два переключения на один спад, цикл 20 мс и запас задержки 20 мс, не принимая интервал спадов более 100 мс.
- Обязательный обдув во всём `PREHEAT`; вектор `GLOW_CMD=1, FAN_CMD=0` запрещён инвариантом ядра и тестом.
- Active-low START/RESET/SET с программным debounce. Удержание START/RESET при включении игнорируется до подтверждённого отпускания.
- OLED показывает `Tset`, `Troom`, `Texh`, `Tair`, состояние и маску причины блокировки; Wi-Fi не нужен.
- MAX31856: continuous conversion, K-type, 50 Hz rejection, все диагностические биты незамаскированы.
- DS18B20: ровно один датчик на шине, 12 бит, проверка CRC/timeout и запрет значения 85 °C после включения.
- Любая потеря обязательного датчика, дисплея, STOP/обрыв, перегрев, неподтверждённое пламя или нарушение инварианта закрывает оба топливных канала.
- Независимый аппаратный выбег вентилятора прошивкой не заменяется и не обходится.

Точный GPIO-контракт: `docs/io-contract.json`.
Пусконаладка: `docs/commissioning_ru.md`.

## Проверка ядра на хосте

```sh
bash tests/run_host_tests.sh
```

Текущий результат: 33/33, включая границу удержание/отпускание RESET, отмену квалификации при блокере, связанную временную модель физической защёлки и проверку худшего интервала спада heartbeat.

## Сборка ESP-IDF 5.5.2

```sh
idf.py set-target esp32s3
idf.py build
```

Или в официальном контейнере:

```sh
docker run --rm -v "$PWD:/project" -w /project espressif/idf:v5.5.2 \
  bash -lc 'idf.py set-target esp32s3 && idf.py build'
```

Проверенная сборка выдаёт:

- `build/bootloader/bootloader.bin` — адрес `0x0`;
- `build/partition_table/partition-table.bin` — адрес `0x8000`;
- `build/sirokko_26201_controller.bin` — адрес `0x10000`.

Актуальный стендовый комплект 0.1.2 находится в `release/firmware/0.1.2/`; контрольные суммы и параметры записи — в его `manifest.json`. Комплекты 0.1.0 и 0.1.1 сохранены без перезаписи.

## Границы готовности

Не проверены на реальном модуле: электрические уровни платы, полярности внешних драйверов, показания датчиков, направление/обороты вентилятора, энергия накала, подача топлива, пламя, независимый watchdog/latch и аппаратный выбег. До стенда устройство должно оставаться без подключённого топлива. Пусковую скорость, времена, температурные пределы и критерии пламени вводят по измерениям, проверяют командой `config validate`, принимают токеном и только затем перезагружают контроллер.
