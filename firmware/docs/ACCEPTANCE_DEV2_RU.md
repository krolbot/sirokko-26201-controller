# Программная приёмка 1.0.0-dev2

## Область результата

Предварительная программная версия ESP32-S3: утверждённый TFT 320×240 landscape, production мобильная веб-страница в flash, единое состояние и один таймер отключения. Это не разрешение запуска горения и не аппаратная квалификация. Плата, GPIO, control core, `app_main.cpp` и `runtime_api.hpp` относительно dev1 не изменены.

## Реализовано

- TFT: штатный `esp_lcd`/ST7789, striped RGB565 DMA, повреждённые плитки обновляются адресно; STOP/fault прерывают обычную презентацию после текущей безопасной передачи.
- Локализованные сцены и кириллица; не добавлены LVGL или второй автомат управления. Волна нагрева действует только в RUN при fuel, температурном режиме, свежем действительном измерении и положительном реальном разрыве. Измеренный маркер не подменяется расчётной температурой.
- Веб: Svelte из `web_ui/`, автономный HTML со шрифтами/лицензиями, детерминированный gzip `web_ui_data.inc`. Страница от production HTTP handler совпадает со сборкой; Node нужен только на машине сборки.
- Только таймер отключения: IDLE задаёт интервал для следующего ручного запуска, активный сеанс — срок от текущего момента, ноль отменяет. Публичные `ARM`/`CANCEL_ARM` запрещены.
- Снимок и challenge сверяются по `state_version`/`boot_id`; внешнее изменение замораживает черновик. STOP идёт независимо от обычного challenge. Превышение времени ожидания означает неизвестный результат, не доказанное отклонение.
- Полный профиль процесса, версия, журнал, датчики с `valid`/`fresh`, плавность регулирования и диагностика читаются из backend. Физические константы не подставлены.
- OTA: очередь `VERIFIED_ACTIVATION_QUEUED` не называется установкой. Ожидаемая версия поступает из проверенного образа; новый boot/version наблюдается и после повторной авторизации. Ошибка/другая версия/timeout не считаются успехом. Авария видна глобально и не перекрывается успешным статусом OTA.

## Разбор независимой проверки

Воспроизведены и устранены слишком широкое условие наблюдения STOP (MAINTENANCE не подтверждает STOP) и перекрытие аварии успешным OTA-уведомлением. До исправления оба отрицательных клиентских теста падали, после проходят.

Предположение о сохранении старого challenge через reboot не подтверждено текущим runtime: boot identity создаётся один раз при старте, HTTP task не продолжается через reset, RAM-сессия, grant и очередь не сохраняются. Host проверяет начальные RAM-состояния после reset: старый cookie получает 401, старый grant после нового входа при совпавшем state_version — 409; команды в runtime не передаются. Это проверка модели reset/handlers, не физический reboot.

## Поставка и воспроизводимость

Код публикуется в `krolbot/sirokko-26201-controller`, версия `v1.0.0-dev2` только как prerelease после успешного CI точного commit. Комплект содержит исходники, native flash binaries/metadata, подписанный `.sota`, журналы, галерею TFT и веб-снимки. В манифесте комплекта находятся точный source commit и SHA-256 каждого файла. Бинарник в `.sota` должен побайтно совпадать с приложенным application `.bin`; production verifier отдельно проверяет подпись и негативные мутации реального пакета. После загрузки release assets скачиваются и сверяются побайтно.

Сборки CI и локальная сборка используют один commit/toolchain, но могут отличаться служебным временем сборки; не объявляются побайтно идентичными без сравнения. Финальные хеши поставки принадлежат манифесту, не этому документу.

## Остаточные ограничения

- `npm audit --omit=dev`: 0 находок. Полный audit: две low-записи одной build-only цепочки `deepmerge` → `@sveltejs/vite-plugin-svelte`, без доступного исправления. [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Недоверенные данные устройства не передаются в конфигурацию сборки; Node и этот пакет не работают на MCU.
- На физическом контроллере не проверены TFT RGB/BGR/offset, органы управления, входы и полярность выходов, NVS, Wi-Fi, установка/откат OTA, SPI/FPS, нагрев и защитные переходы.
- Профиль процесса без подтверждённых параметров не становится квалифицированным. `F1 fuse_trip_unknown` не закрыт; номинал 15 A не доказан как порог защиты.
- Физическая прошивка, запуск оборудования и горение не выполнялись.
