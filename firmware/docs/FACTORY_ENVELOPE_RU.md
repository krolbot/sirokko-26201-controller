# Подготовка исходных ограничений сборки

`tools/prepare_factory_envelope.py` создаёт офлайн запись `sirokko/envelope_v1` для загрузчика в `app_main`. Это отдельная подготовка конкретной конструкции, **не ручной профиль пользователя перед каждой калибровкой**. Инструмент ничего не записывает в устройство.

## Что требуется на входе

JSON с ровно двумя полями:

- `qualification_reference`: ссылка или идентификатор отчёта квалификации конкретной сборки. Непустая строка сохраняется в манифесте, но её наличие не доказывает квалификацию.
- `envelope`: все числовые поля `SafetyEnvelope`, кроме `provisioned`. Пропуски, неизвестные и повторяющиеся ключи отклоняются. Времена — целые миллисекунды, температуры и приращения — целые тысячные градуса Цельсия, команды — целые коды привода. Имена полей перечислены в `TIMES`, `TEMPERATURES`, `CODES` самого инструмента.

Рабочего численного примера для нагревателя намеренно нет: квалифицированные исходные данные этой сборки ещё не получены. Значения из `tests/test_factory_envelope.py` — исключительно синтетические и непригодны для подготовки устройства.

## Воспроизводимый запуск

Из `firmware` в окружении ESP-IDF 5.2.3 с компиляторами ESP32-S3 и host g++:

```sh
python tools/prepare_factory_envelope.py --input /path/to/qualified-envelope.json --output-dir /path/to/new-output
```

Выходной каталог не должен существовать. Результат:

- `envelope_v1.bin` — запись с magic `0x454E5631`, версией кодека 2 и контрольной суммой;
- `envelope.csv` — вход для штатного генератора NVS ESP-IDF;
- `manifest.json` — исходные значения, ссылка на квалификацию, размер, смещение checksum и SHA-256.

Сначала настоящий host-валидатор `valid_safety_envelope()` проверяет значения. Затем **целевой компилятор** формирует представление структуры и метаданные смещений; Python не предполагает, что раскладка полей ESP32-S3 совпадает с x86. Сгенерированные целевым компилятором байты проверяются реальным кодеком в тесте, включая явную проверку совпадения layout для host-декодирования.

`envelope.csv` содержит относительный путь к blob; генератор NVS запускается из выходного каталога. Размер раздела и адрес должны браться из конкретного производственного комплекта, не из синтетического теста. Подготовка полного образа NVS не является безопасным обновлением существующего раздела: его перезапись может уничтожить настройки и сетевые реквизиты. Команды записи или стирания здесь намеренно не приводятся.

## Проверка

```sh
python tests/test_factory_envelope.py
```

Выполнено в имеющемся контейнере ESP-IDF 5.2.3, без сети, с лимитом памяти: строгая схема и дубли ключей, диапазоны типов, семантически неверные ограничения, детерминированное целевое кодирование, чтение реальным кодеком, отказ при повреждении, запуск CLI и создание синтетического образа штатным генератором NVS — PASS. Все синтетические артефакты теста удаляются его временным контекстом.

Прошивка при отсутствии или повреждении исходной записи не подставляет значения из тестов и не разрешает топливо. Численная валидация и checksum не подтверждают безопасность физической сборки и не являются криптографической аутентификацией отчёта.
