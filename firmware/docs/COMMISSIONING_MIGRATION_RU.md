# Переход к модели ввода в эксплуатацию — локальная проверка

Это описание текущих локальных изменений после dev3, а не опубликованного выпуска. Версия в существующей конфигурации сборки остаётся `1.0.0-dev3`; новый бинарный файл не следует путать с опубликованным артефактом dev3.

## Разделение данных

- `SafetyEnvelope` — исходные ограничения конкретной сборки, не результат температурного обучения.
- `LearnedOperatingModel` — полученный диапазон команд, измеренные характеристики, происхождение и fingerprint.
- `CommissioningSnapshot` — типизированные этап, причина, запрет, прогресс и идентичность результата.
- `LearnedModelRevision` — ручная коррекция существующего результата; требует ожидаемой ревизии, разрешает только сужение диапазона и уменьшение темпа изменения команды.

Старого рабочего пути `ProcessProfile`/`OperatingRange` и команды `PROCESS_CONFIG` больше нет. Отрицательные тесты сохраняют старые имена специально: прежний запрос должен отклоняться.

## Сохранение

Используются `model_stage4`, `model_active4` и отдельные `settings_v2`. Промежуточная запись не становится действующей моделью при загрузке. Ручная ревизия сначала создаётся на копии контроллера; изменение живой модели выполняется после принятия записи и проверки прочитанного результата. При STOP до принятия записи кандидат отменяется; после принятия нельзя обещать отмену уже выполненного долговечного действия.

## Дополнительная проверка выявила дефекты

Первоначальный PASS после миграции был недостаточен: в одном промежуточном варианте runtime-тест потерял сценарии межзадачных гонок. Полный набор восстановлен; текущая проверка выше проходит также под ASan/UBSan. Текущая власть тестов — production runtime/контроллер с NVS-моделью; это не модель электрического пропадания питания.

Исправлены расхождения условий ревизии: HTTP и владелец состояния теперь используют общий `valid_model_revision`; равные границы, нулевой/слишком малый темп и переполнение ревизии отклоняются до выдачи разрешения. Клиент имеет те же численные ограничения. Дополнительные клиентские и настоящие HTTP-тесты прошли. Исправлена установка суженной модели: уменьшенный максимум не должен требовать равенства исходной опорной команде.

Темпы `model.slew_*` — сохранённые ограничения настроек в долях диапазона/с, **не автоматически найденные тепловые пределы**. `measurements.observed_slew_*` — диагностическое наблюдение команд в кодах/с; его наличие не доказывает безопасность более быстрого перехода.

## Незакрытый критерий

Производственно квалифицированные исходные численные ограничения для реального отопителя в проект не переданы. Поэтому офлайн-генератор проверен только на явно синтетических данных, а пустая/повреждённая NVS безопасно блокирует топливо. До заполнения `SafetyEnvelope` данными конкретной квалификации нельзя считать автоматическую калибровку разрешённой к запуску на оборудовании. Заводские номинальные температуры не преобразованы в защитные пределы.

Проверка полного тестового стенда подтверждает программные контракты, но не физические GPIO, датчики, NVS при brownout, OTA-перезагрузку/rollback или горение. Прошивку на реальное устройство не записывали; готовый пакет и публикация пока не сформированы.
