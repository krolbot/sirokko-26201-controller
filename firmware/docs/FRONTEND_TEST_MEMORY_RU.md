# Ограничение памяти проверки встроенной страницы

## Причина

`test_web_frontend.js` сравнивал gzip и HTML через `assert.deepEqual(Buffer, Buffer)`. При различии Node формирует подробный diff бинарных массивов; именно диагностический путь может потреблять несоразмерную память. В текущем дереве HTML из встроенной страницы имеет 456493 байта, локальный dist — 453012 байт. Они действительно различаются; проверку нельзя удалять или объявлять успешной.

Воспроизведено на Node v26.7.0 с этими файлами. Старое сравнение в отдельном systemd user service (MemoryMax=256M, MemorySwapMax=0, RuntimeMaxSec=15s) и V8 heap64MiB завершилось ошибкой heap OOM, exit134, peak RSS119132KiB. Не воспроизводили неограниченный расход10ГиБ на хосте gateway.

## Исправление

- `binary_contract.cjs`: точное `Buffer.equals`; при несовпадении компактная ошибка с длинами, первым несовпадающим смещением и SHA256. Полные буферы не помещаются в объект ошибки.
- Оба бинарных сравнения в `test_web_frontend.js` используют эту функцию. Малые структурированные JSON-проверки сохранены.
- `test_web_ota_host.py`: Node запускается с `--max-old-space-size=128` и внешним timeout60s; timeout явно обрабатывается как провал. Ограничение V8 не является жёстким лимитом всего RSS. Проверочные локальные запуски дополнительно ограничены системным MemoryMax.
- `test_binary_contract.cjs` встроен в последовательность host runner: равные/пустые данные, разные длины, изменения в начале/середине/конце, типы,100повторных отказов, ограниченная длина сообщения.

## Фактическая проверка

- Исправленный реальный `test_web_frontend.js` на копии встроенного page.bin и текущем несовпадающем dist: ожидаемый exit1,0.50s, peak RSS110016KiB; понятная ошибка binary mismatch, первое различие1886. Это проверка отрицательного пути, НЕ положительная приёмка всего frontend. Для этой проверки нужны только page.bin: ошибка возникает до чтения остальных fixture-файлов.
- `test_binary_contract.cjs`: PASS, exit0,0.46s, peak RSS84856KiB; V8heap64MiB, OS memory256MiB.
- Gateway и соседние процессы не изменялись и не перезапускались. Во время первой проверки активного test_web_frontend.js уже не было.

Полная интеграционная сборка автокалибровки остаётся отдельной незавершённой работой. Несовпадение встроенной страницы и dist необходимо устранить общей пересборкой после завершения изменений UI; оно не маскируется этим исправлением.
