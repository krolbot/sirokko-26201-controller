# Выполненные проверки и границы — 0.1.8-DRAFT

## Источник и целевая сборка

Реализация опубликована в main commit 3ef88c6cbd13ba83593f9e24cf222d2f79f0906b. GitHub refs/tree и все 34 изменённых raw-файла прочитаны обратно; bytes/SHA256/Git blob SHA совпали. Контракт опубликован ранее отдельным WIP 60586ca46fe6003d696adda87089bcf24249f2ab. Новые NKK-материалы опубликованы отдельным WIP c0969efb6de806dac5845e2701c98f2ecd88140c; readback всех шести изменённых файлов совпал. Исходные схема/PCB/компоненты не менялись, единственное изменение hardware/ — SHA256SUMS для общего CURRENT_STATE.

Вход native-build собран из Git без release-каталогов, с зафиксированными sdkconfig/dependencies.lock и управляемыми компонентами из прежнего комплекта. Входной архив передан на Lab; удалённые SHA архива и каждого файла сравнивались с локальными до компиляции. Каталог build отсутствовал. Использован уже существующий ESP-IDF image sha256:05cbfc42ed2e987b8026722c15bf1d8523d3e4fd1b4ac04d2e4056f5e0918b99, 2CPU/4GB/512PID, cap_drop ALL, no-new-privileges, без портов/устройств и без установки пакетов. Настоящая сборка завершилась exit 0. Метаданные считаны esptool из полученных bin, таблица разделов декодирована штатной gen_esp32part.py. Обратный архив с результатами также проверен по SHA.

Сохранены два предупреждения CMake об опциональном DS18B20_SENSOR_HUB и повторном конфигурировании. Это не ошибки компиляции; скрывать их или менять внешнюю зависимость в этой задаче не стали. IDF v5.5.2/commit 30aaf64524299d3bde422ca9a2848090d1bc5d0f подтверждены непосредственно контейнером.

## Исполненные программные проверки

Полный штатный набор на рабочем исходнике и повторно на распакованном exact build-input: 110/110 C++ групп — 50 baseline, 11 feature, 11 runtime, 4 display/SPI-model, 13 DRAFT-06, 4 UI, 17 network. Python service-artifacts: 4/4. Это запуск production source с имитацией RTOS/периферии/NVS/flash/TLS/otadata, плюс настоящий OpenSSL RSA-3072/SHA256 в сетевых проверках; не испытание платы.

Новые 13 групп: short/long/debounce/wraparound, boot-held и смена роли/запрета, один long и отсутствие short после него; GPIO8 released-init/settling/реальный pad против старого регистра/heartbeat последним; ошибки API/несовпадение уровня и защёлкивание FAULT_OUTPUT; recovery без ожидания собственного LOW/SAFETY_OK; RESET с held START/обязательной продувкой; настоящий schema-3 blob от старого CommissioningStore, отказ автоматической приёмки и явная новая schema 4/contract 6; short только UI; long STOP во всех семи активных стадиях; приоритет RESET/FAULT/OTA/service; boot-held RESET/START; held STOP без повторного старта и без сокращения продувки.

Старая NC STOP GPIO8-матрица несовместима с новым направлением вывода. Её немедленный STOP-смысл сохранён для сервисного STOP, а локальный long STOP проверен отдельно. Остальные старые корректные проверки сохранены. Legacy blob — реальная сериализация старым кодом с валидной прежней приёмкой, но на host ABI, не дамп физического NVS ESP32.

Дополнительно verification/reset_skew.cpp исполняет настоящую control_task при независимом изменении GPIO6 и SAFETY_OK: B без A; A после отпускания B; B раньше A; A раньше B; потеря SAFETY_OK до отпускания B; длительный B без аппаратного принятия; B удержан до готовности; START удержан на RESET. Разрешаются оба порядка полюсов только с обратным SAFETY_OK, отказы не создают горение. Все 8/8 сценариев и 32 комбинации PG/WD/THERMAL/ARM/TRIP при stuck-LOW GPIO8 прошли. Эти времена выбраны как тестовые примеры, не паспортные пределы NKK; непрерывный диапазон механического рассогласования не квалифицирован.

Восемь статических NKK-контактных случаев (6 допустимых/2 MBB отрицательных) — отдельный инженерный расчёт, не ещё восемь firmware-тестов. Аналогично модель 4096 сочетаний не заменяет исполненную host-регрессию.

## Интерфейс и ограничения

12 PNG получены общим production RGB565BE renderer и просмотрены как симуляция. Кириллица и версия 0.1.8-DRAFT читаются, «КОРОТКО: ГЛАВНАЯ» не обрезается. Унаследованные ограничения: BENCH ONLY не повторяется на SETTINGS/RESET_COUNTERS, подсказка короткого нажатия сокращена и требует инструкции; реальный контраст/цвет/ориентация не проверены. Не расширяли задачу до переработки интерфейса.

Физическая плата не подключалась, не прошивалась, силовые нагрузки/топливо не подключались. Электрические уровни, VOL/VIL, transient/glitch, реальные контакты/reset/watchdog, датчики, SPI arbitration/TFT, NVS power-cut, реальные OTA/rollback/сеть не испытаны. Работа программного RESET не гарантирует исправность аппаратуры. Старый внешний NC STOP опасно несовместим. NKK BB25AB-FA функционально документирован, но остаётся DRAFT/NOT FOR ORDER по закупке/механике/интеграции. Производственный допуск не выдан, общая инженерная задача не закрыта.
