# Кнопки, экраны и сохранение — 0.1.6-DRAFT / BENCH ONLY

## Приоритет кнопок

- STOP напрямую обрабатывается каждым проходом автомата: снимает топливо/накал, сохраняет требуемую продувку, возвращает меню на главный экран. Он не ждёт длинного жеста меню.
- START — только новый локальный фронт ручного пуска. Меню не перехватывает его и не использует для подтверждения. Пуск проходит все проверки профиля, датчиков, STOP, аппаратной защиты, охлаждения, restart inhibit и сервисной блокировки. Пуск, отклонённый во время обслуживания, после освобождения не повторяется сам.
- RESET — отдельный согласованный физический цикл аппаратной защёлки из `commissioning_ru.md`; меню его не использует. RESET не является START. Удержание при включении не создаёт новый допустимый фронт.
- SET_UP / SET_DOWN (на экране UP/DN) — только настройки. На главном экране одиночное нажатие меняет уставку на 0.5 °C в пределах принятого профиля.

## Навигация

1. Для входа в настройки удерживать обе SET-кнопки не менее 800 мс.
2. Полностью отпустить обе. Одиночными UP/DN выбрать пункт, снова удержать обе 800 мс для открытия.
3. В редактировании одиночные нажатия изменяют число; обе 800 мс возвращают в список. Настройка применяется в RAM сразу, но не меняет инженерные пределы профиля.
4. В диагностике/профиле/версии одиночное нажатие или обе кнопки возвращают в список. STOP всегда возвращает домой, одновременно выполняя свою настоящую остановку отопителя.
5. После 30 с бездействия меню закрывается. Уже удерживаемое сочетание не создаёт повторных команд: требуется отпустить обе кнопки. Сочетание, зажатое при boot, игнорируется до отпускания.

| Экран | Содержание / действия |
|---|---|
| Главный | Комната/уставка, гистерезис и зона, EXH/AIR, этап/остаток времени, вентилятор % команды, муфта/свеча/permit как команды, причина запрета пуска/авария. Не RPM и не измеренные контакты. |
| Уставка | Шаг 0.5 °C, min/max из профиля, состояние сохранения NVS. |
| Гистерезис | Полная ширина 0.5..10.0 °C, шаг 0.5 °C; default 1.0 °C. Пороги регулируются относительно центра исходного профильного диапазона. |
| Смещение комнаты | Поправка ±10.0 °C, шаг 0.1 °C; только DS18B20. Неверное исходное измерение не превращается в исправное. |
| Диагностика | Комната raw/calibrated, EXH/AIR raw, качество/возраст всех каналов, байты MAX31856 fault, STOP и аппаратный SAFETY_OK. |
| Профиль | Приёмка/токен/ревизия, квалификация малого режима, заданные PWM/продувка, пределы уставки и исправность памяти/настроек. Токен — контроль конфигурации, не пароль доступа. |
| Счётчики | Запуски/неудачи, время команд работы/накала, последнее состояние/причина, boot/session. Обе кнопки 800 мс открывают подтверждение сброса. |
| Подтверждение сброса | Отпустить обе, затем НОВОЕ одновременное удержание 2 с. Одиночное нажатие — отмена. Очищаются только счётчики, не авария, не журнал, не commissioning. |
| Версия | Версия настоящего образа, target, состояние сети/обновления; всегда BENCH ONLY. |

## NVS и потеря питания

Настройки имеют отдельную schema 1, инженерный профиль — schema 3. Уставка, гистерезис и поправка хранятся одним проверяемым blob с digest; счётчики, журнал и latched faults — отдельные ограниченные записи. Нет общего атомарного транзакционного снимка всех ключей: каждая запись целостна отдельно.

Периодическая задача не пишет flash во время розжига, RUN или обязательной продувки. Попытки записи разнесены минимум на 5 с, редкий снимок счётчиков — не чаще принятого периода задачи; ошибки замедляют повторы до 60 с и блокируют опасный пуск. Поэтому после изменения экран честно показывает «NVS: НЕ СОХРАНЕНО / ПОСЛЕ ОСТАНОВКИ». При внезапном выключении последние изменения и часть командного времени могут быть потеряны; это не энергонезависимый приборный учёт.

Повреждённая/неизвестная запись не заменяется автоматически defaults и не стирается при ошибке `nvs_flash_init`. START блокируется. Локальная команда `settings save` после полного безопасного останова — явное подтверждение восстановления только операторской записи; это не универсальное восстановление повреждённых counters/history/faults. Для критичных повреждений сначала сохранить NVS, выяснить причину и согласовать ремонт, не применять `erase_flash` как «лечение».

USB-диагностика: `status`, `counters`, `history` (RAM), `history saved` (сохранённый журнал). Времена монотонные с boot/session, не выдуманная календарная дата. CLI `settings setpoint|hysteresis|offset <целые миллиградусы>` меняет RAM через очередь; ответ QUEUED ещё не означает сохранённую NVS.

## Изображения

`tests/render_ui.cpp` вызывает тот же `render_ui_band`, что production TFT. Он создаёт 12 кадров P6 PPM 240×320 из восьми полос RGB565BE. `python3 tools/render_previews.py build-host/ui` делает PNG и contact sheet без внешних библиотек. Изображения в комплекте — явно программная симуляция: в том числе принятый пример профиля и искусственная ошибка AIR. Их числа не являются измерениями платы или готовыми параметрами горения.

Физически проверить кириллицу, цвета RGB565, ориентацию, холодный старт и чтение пяти кнопок необходимо отдельно. У GMT020-02-7P нет MISO/TE/датчика присутствия; успешная запись SPI не доказывает, что снятая панель показывает кадр.
