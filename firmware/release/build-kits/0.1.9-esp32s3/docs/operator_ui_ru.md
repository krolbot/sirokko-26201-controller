# Кнопки, экраны и сохранение — 0.1.9-DRAFT / BENCH ONLY

## Приоритет кнопок

- Ровно четыре кнопки: START_STOP GPIO7, SET_UP GPIO39, SET_DOWN GPIO40, RESET GPIO6. Отдельной мгновенной NC STOP нет. Старая плата несовместима с draft-06 до аппаратного внедрения; RESET MPN/BBM/посадка HOLD.
- START_STOP: debounce 30 мс; short после отпускания переключает только ГЛАВНАЯ↔НАСТРОЙКИ. Long 1500 мс в разрешённом ожидании запрашивает ручной START; в подготовке/розжиге/RUN снимает запрос тепла, топливо/накал OFF до штатной постпродувки. Один long за удержание, без short на отпускании после long. В recovery/POST_PURGE/LOCKOUT/OTA long не прерывает защиту и не ставит пуск в очередь; удержание при boot или изменении запрета требует отпускания и нового жеста. Текущие отказы, RESET и обслуживание приоритетнее START. Удалённый сервисный STOP по-прежнему снимает тепло без ожидания жеста.
- RESET — отдельный согласованный физический цикл аппаратной защёлки из `commissioning_ru.md`; меню его не использует. RESET не является START. Удержание при включении не создаёт новый допустимый фронт.
- SET_UP / SET_DOWN (на экране UP/DN) — только настройки. На главном экране одиночное нажатие меняет уставку на 0.5 °C в пределах принятого профиля.

## Навигация

1. Для входа в настройки коротко нажать START_STOP либо удерживать обе SET-кнопки не менее 800 мс.
2. Полностью отпустить обе. Одиночными UP/DN выбрать пункт, снова удержать обе 800 мс для открытия.
3. В редактировании одиночные нажатия изменяют число; обе 800 мс возвращают в список. Уставка, гистерезис и поправка применяются в RAM сразу. Два таймера имеют отдельное подтверждение ниже; промежуточные числа не действуют. Инженерные пределы профиля не меняются.
4. В диагностике/профиле/версии одиночное нажатие или обе кнопки возвращают в список. Короткий START_STOP возвращает домой без изменения тепла; принятый long STOP возвращает домой со штатным остановом.
5. После 30 с бездействия меню закрывается. Уже удерживаемое сочетание не создаёт повторных команд: требуется отпустить обе кнопки. Сочетание, зажатое при boot, игнорируется до отпускания.

| Экран | Содержание / действия |
|---|---|
| Главный | Комната/уставка, гистерезис и зона, EXH/AIR, этап/остаток времени, вентилятор % команды, муфта/свеча/permit как команды, причина запрета пуска/авария. Не RPM и не измеренные контакты. |
| Уставка | Шаг 0.5 °C, min/max из профиля, состояние сохранения NVS. |
| Гистерезис | Полная ширина 0.5..10.0 °C, шаг 0.5 °C; default 1.0 °C. Пороги регулируются относительно центра исходного профильного диапазона. |
| Смещение комнаты | Поправка ±10.0 °C, шаг 0.1 °C; только DS18B20. Неверное исходное измерение не превращается в исправное. |
| Диагностика | Комната raw/calibrated, EXH/AIR raw, качество/возраст всех каналов, байты MAX31856 fault, STOP и аппаратный SAFETY_OK. |
| Профиль | Приёмка/токен/ревизия, квалификация малого режима, заданные PWM/продувка, пределы уставки и исправность памяти/настроек. Токен — контроль конфигурации, не пароль доступа. |
| Счётчики | Запуски/неудачи, время команд работы/накала, последнее состояние/причина, boot/session. Обе кнопки 800 мс открывают подтверждение сброса. |
| Подтверждение сброса | Отпустить обе, затем НОВОЕ одновременное удержание 2 с. Одиночное нажатие — отмена. Очищаются только счётчики, не авария, не журнал, не commissioning. |
| Версия | Версия настоящего образа, target, состояние сети/обновления; всегда BENCH ONLY. |

## Два независимых относительных таймера

«Время работы» и «Отложенный пуск» — отдельные пункты списка (UP от первого пункта дважды/один раз). Короткий START_STOP открывает выбранный пункт. Часы редактируются отдельно 0..24, минуты 0..59; при 24 ч минуты только 00. 0:00 — OFF, минимум включённого таймера 0:01. Короткий START_STOP последовательно открывает часы → минуты → подтверждение; UP на подтверждении — «Применить», DOWN — «Отмена», короткий START_STOP — выход без применения. Тайм-аут 30 с/уход в список/STOP/FAULT также отменяют промежуточное значение.

Длительность начинает отсчёт при принятом START и переходе WAIT_COOLDOWN→PREPURGE, включая подготовку и розжиг, но не время задержки и не завершающую продувку. Во время активной сессии явное применение ненулевого значения, даже прежнего, начинает новый отсчёт СЕЙЧАС. OFF выключает только этот таймер, не топливо и не сессию. Истёкший старый дедлайн нельзя отменить одновременным Apply: сначала штатный STOP с причиной TIMER, топливо/накал OFF и обычная минимальная продувка до охлаждения. STOP/FAULT приоритетнее таймера; после охлаждения — ожидание нового ручного пуска, без автоматического повторения по термостату.

Применение задержки только сохраняет настройку. Чтобы взвести её в разрешённом ожидании, полностью отпустить START_STOP и выполнить НОВОЕ долгое нажатие 1500 мс. Уже удерживаемая до Apply кнопка не подходит. При OFF тот же новый long запрашивает обычный немедленный ручной START. При включённой задержке экран явно показывает ВЗВЕДЁН, остаток и длительность будущей работы; топливо и накал выключены. Исходное удержание не повторяется. Новый long отменяет ожидание: на холодной установке без топлива он не запускает ненужную продувку. Удалённый STOP, RESET, авария, явное OTA/обслуживание также отменяют взведение. Внутреннее автосохранение откладывается, а не отменяет выбор оператора, в том числе при гонке со старым снимком.

По окончании задержки запрос погашается ОДИН раз и заново проверяются профиль/настройки, актуальность всех датчиков, охлаждение, спрос термостата, аппаратная защита, выходы и запрет обслуживания. При отказе экран показывает отмену/причину; скрытой очереди «пока остынет/похолодает» нет. При успехе начинается обычная PREPURGE и независимый таймер работы. После STOP/отказа/окончания сессии требуется новое явное локальное взведение. MQTT/USB-команд на START, взведение или изменение таймеров нет.

RTC, календарь, сеть и SNTP для этих двух таймеров не используются. В NVS могут сохраняться только выбранные интервалы, не взведение/дедлайны/RUN. После каждого reboot — существующая RECOVERY_PURGE, физическая приёмка/RESET по её правилам и новый локальный жест; активные таймеры не восстанавливаются.

## NVS и потеря питания

Настройки имеют отдельную schema 2 (`operator_v2`), инженерный профиль — прежнюю schema 4, обязательный `hardware_contract_id=6`. Корректная операторская запись schema 1 читается отдельной старой структурой: прежние уставка/гистерезис/поправка сохраняются, оба новых таймера OFF. Ключ `operator_v1` не перезаписывается; сохранение новых настроек идёт только в `operator_v2`. Повреждённая/неизвестная v2 не заменяется старой v1 молча. Прежний принятый draft-05 не мигрируется автоматически; нужен новый ручной ввод/приёмка после проверки новой проводки, без переноса RUN. Настройки хранятся одним проверяемым blob с digest; счётчики, журнал и latched faults — отдельные ограниченные записи. Нет общего атомарного транзакционного снимка всех ключей: каждая запись целостна отдельно. Старые числовые значения `history_v1` сохранены; TIMER/DELAY_ARMED/DELAY_CANCELLED добавлены в конец enum. Старый образ может не прочитать новый журнал и не увидит новые настройки: произвольный откат без сохранения NVS не обещается.

Периодическая задача не пишет flash во время розжига, RUN или обязательной продувки. Попытки записи разнесены минимум на 5 с, редкий снимок счётчиков — не чаще принятого периода задачи; ошибки замедляют повторы до 60 с и блокируют опасный пуск. Поэтому после изменения экран честно показывает «NVS: НЕ СОХРАНЕНО / ПОСЛЕ ОСТАНОВКИ». При внезапном выключении последние изменения и часть командного времени могут быть потеряны; это не энергонезависимый приборный учёт.

Повреждённая/неизвестная запись не заменяется автоматически defaults и не стирается при ошибке `nvs_flash_init`. START блокируется. Локальная команда `settings save` после полного безопасного останова — явное подтверждение восстановления только операторской записи; это не универсальное восстановление повреждённых counters/history/faults. Для критичных повреждений сначала сохранить NVS, выяснить причину и согласовать ремонт, не применять `erase_flash` как «лечение».

USB-диагностика: `status`, `counters`, `history` (RAM), `history saved` (сохранённый журнал). Времена монотонные с boot/session, не выдуманная календарная дата. CLI `settings setpoint|hysteresis|offset <целые миллиградусы>` меняет RAM через очередь; ответ QUEUED ещё не означает сохранённую NVS.

## Изображения

`tests/render_ui.cpp` вызывает тот же `render_ui_band`, что production TFT. Он создаёт кадры P6 PPM 240×320, включая оба таймера, из шестнадцати полос RGB565BE 240×20. `python3 tools/render_previews.py build-host/ui` делает PNG и contact sheet без внешних библиотек. Изображения в комплекте — явно программная симуляция: в том числе принятый пример профиля и искусственная ошибка AIR. Их числа не являются измерениями платы или готовыми параметрами горения.

Физически проверить кириллицу, цвета RGB565, ориентацию, холодный старт и чтение четырёх кнопок необходимо отдельно. У GMT020-02-7P нет MISO/TE/датчика присутствия; успешная запись SPI не доказывает, что снятая панель показывает кадр.
