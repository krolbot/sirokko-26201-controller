## Управление

Сохранены четыре существующие стендовые кнопки по актуальному UX: START_STOP GPIO7, UP39, DOWN40, RESET6; GPIO не менялись. Прежняя концепция отдельных ПУСК/СТОП и энкодера историческая, не текущая цель. Это программная интеграция, НЕ физическая приёмка панели/компонентов или изменение аппаратных контактных функций. Полный порядок — docs/operator_ui_ru.md. Два таймера OFF либо 1 мин…24 ч:

- Время работы считает с принятого START→PREPURGE, включая подготовку/розжиг. Истечение — обычный STOP с отдельной причиной TIMER, fuel/glow OFF и обязательная продувка/охлаждение. Повторного пуска по термостату нет.
- В активной сессии явное Apply ненулевого времени начинает отсчёт сейчас. OFF отключает только таймер, не сессию. Промежуточная правка/отмена/выход действующий отсчёт не меняют.
- Применение задержки НЕ взводит её. В разрешённом ожидании нужен новый локальный long START_STOP 1500 мс после отпускания. Исходное удержание не повторяется. Новый long отменяет ожидание; на холодной установке без топлива не создаёт ненужную продувку.
- По окончании задержки — одна повторная проверка текущих запретов и либо обычный START, либо отмена с причиной. Нет скрытого ожидания разрешения. STOP/RESET/FAULT/явное OTA/обслуживание отменяют ожидание; внутренний AUTOSAVE откладывается, включая гонку со старым снимком.
- Часы, минуты и подтверждение редактируются отдельно. На подтверждении UP=Применить, DOWN=Отмена, short=выход без применения. OFF=0:00, максимум24:00.
- RTC/NTP/сеть не нужны. Активные отсчёты/взведение/RUN не сохраняются. После reboot — RECOVERY_PURGE и новый локальный жест. Рабочего MQTT/OTA ключа или брокера не добавляли; удалённых START/RESET/настроек таймеров нет.

## Повтор без устройства

Из каталога комплекта:

    python3 verify.py
    mkdir rebuild host-deps
    tar -xzf source/firmware-source.tar.gz -C rebuild
    tar -xzf build-config/cjson-source.tar.gz -C host-deps
    SIROKKO_CJSON_DIR="$PWD/host-deps/cJSON" bash rebuild/firmware/tests/run_host_tests.sh
    python3 rebuild/firmware/tools/render_previews.py rebuild/firmware/build-host/ui

Нужны уже установленные C++20/C, Python3, OpenSSL development headers/libcrypto. Ничего не устанавливать автоматически; --core-only не заменяет полный прогон.

Целевая сборка в существующем Docker с уже загруженным pinned образом:

    cp build-config/compose.yaml rebuild/compose.yaml
    cd rebuild
    docker compose -p sirokko-019-rebuild run --rm idf

Рецепт pull_policy=never, 2 CPU/4 GB/512 PID, cap_drop=ALL/no-new-privileges, без портов. Требуется исходящий Component Registry: успешная сборка использовала штатный manager для metadata/зависимостей. Все 61 файла двух существующих управляемых компонентов побайтно совпали с прежним окружением; их код/manifest не исправлялись, пакеты/образы не устанавливались. Офлайн-сборка НЕ обещается: попытка с network=none не разрешила registry metadata; отключение manager потеряло объявленную в manifest зависимость ds18b20→onewire_bus. Обе неудачные попытки сохранены отдельно, не выданы за успешный build. Предупреждение optional DS18B20_SENSOR_HUB и штатный повтор Kconfig раскрыты в журнале. Время компиляции меняет бинарный hash; побайтовая воспроизводимость новой target-сборки не заявляется.

## Физическая запись — НЕ выполнена и сейчас не разрешена

После отдельного утверждения совместимой аппаратуры, порта/стенда без топлива, проверки GPIO8/safety/RESET и сохранения NVS разрешённый оператор пользуется официальным esptool. Из firmware/ этого комплекта:

    python -m esptool --chip esp32s3 -b 460800 --before default_reset --after hard_reset write_flash @flash_args

Фактические offsets: bootloader0x0, partition-table0x8000, otadata0x10000, app0x20000; второй OTA-слот0x320000. Не использовать старый app0x10000, не выполнять erase_flash и не прошивать работающий отопитель. Новые операторские настройки schema2/operator_v2 читают проверенную v1 с таймерами OFF, не перезаписывая старый ключ. Профиль остаётся schema4/hardware_contract_id6 и не принимается автоматически. Новые причины журнала могут быть непонятны старому образу: произвольный откат без сохранения NVS не обещается.

Нет физической квалификации GPIO/SPI/TFT/датчиков/реле/питания/защёлки/watchdog, ЭМС/тепловых запасов, Wi-Fi/TLS/MQTT/OTA/rollback или горения. eFuse/secure boot/flash encryption и службы не менялись. Сторонние PDF и секреты в комплект не включены; лицензии неизменённых Espressif-компонентов и cJSON сохранены в исходниках.
