## Выбранный способ

Два независимых one-shot измерителя, запуск параллельно по времени, обмен SPI раздельно по CS. Период запуска каждого 250 мс, усреднение 1 выборка, тип K, внутренний холодный спай включён. Фильтр 50 Гц — инженерный исходный выбор с возможностью заменить на 60 Гц по фактической помехе, не вывод о стране эксплуатации. Смена фильтра только вне преобразования. Шина SPI 1 МГц; режим и физические GPIO сверить с действующим полным I/O-контрактом перед реализацией.

Основание: в automatic mode тест обрыва проходит раз в16 преобразований. One-shot при включённом OCFAULT проверяет обрыв при каждом запуске (стр.14). Частое чтение SPI не ускоряет автоматический тест. One-shot обеспечивает регулярный тест без новой аппаратуры.

Режим OCFAULT=01 применять только при подтверждённом RS<5кОм по таблице4; граница требует входного условия на подключаемую термопару/провод. Для исходной низкоомной проводки назначено проектное требование сопротивления петли не более100Ом. Это собственное ограничение совместимости, а не измерение имеющихся зондов; типK сам по себе не подтверждает сопротивление, изоляцию спая или точность. Фактические ёмкости и обрыв каждого провода проверить на стенде до допуска. При неподходящей проводке не переключать скрыто режим, а пересчитать задержку и контракт.

Предлагаемые регистры CR1=0x03; CR0 в покое0x15, запуск0x55: CMODE0,1SHOT по команде,OCFAULT01,CJ enabled,interrupt fault mode,50Hz. Значения вычислены из описания битов стр.19–20. Это не проверенная конфигурация реального экземпляра. Записывать, читать обратно устойчивые биты; самосбрасывающиеся биты проверять по назначению. После старта не очищать аварийный статус автоматически.

## Временной бюджет

По стр.4 one-shot 50Hz: max185мс; по табл.4 OCFAULT01,CJ on: max15мс. Для планирования резервируется консервативная сумма200мс; это запас по расписанию, не утверждение, что внутренние этапы всегда идут последовательно. Часть операций CJ/обрыв выполняется одновременно.

Назначено10мс на обслуживание готовности/чтение/проверку; завершение не позднее210мс от запуска. При периоде250мс остаётся40мс резерва. Эти10мс должен подтвердить исполнитель тестом планировщика под сетевой нагрузкой. Одна транзакция8байт на1МГц занимает64мкс без учёта CS/драйвера; это только расчёт передачи, не измерение всей задачи.

Для обрыва в произвольной фазе, в том числе сразу после уже выполненного теста текущего цикла, принята заведомо консервативная оценка наблюдения:
 t_observe <= 2*250 + 200 + 10 = 710мс.
Это расчётная оболочка расписания для исправного измерителя и подтверждённой входной цепи, не гарантированное время отключения топлива. В неё не входят задержка реле, неисправность контактов или выбег процесса. На стенде обрывать каждый провод каждого канала в разных фазах и подтвердить эту границу; при превышении вернуть контракт на пересмотр.

## Готовность и достоверность

1. Использовать существующие DRDY обоих каналов. Перед очередным запуском исключить остаточную готовность старой выборки; после чтения регистров температуры DRDY возвращается HIGH (стр.17). Проверить последовательность HIGH→новый LOW для каждого запуска, включая быстрый отрицательный сценарий. Нельзя объявлять новую выборку только потому, что температура изменилась или истекло200мс.
2. От запуска до210мс должна завершиться свежая выборка. Нет нового DRDY, SPI ошибка, неверное чтение конфигурации или неполный пакет — неисправность измерительного канала; прежнюю температуру не переименовывать в свежую. Неподвижная температура при штатном DRDY сама по себе не неисправность.
3. Читать три байта линейной температуры одним multibyte transfer; холодный спай двумя байтами одной передачи. Читать SR0Fh до и после пакета; если появилась ошибка, выборку не принимать. Отдельно проверять все значимые биты диапазона,OVUV,OPEN и установленные температурные пороги. Начальный MASK=FF не означает отсутствие ошибок: маска управляет выводомFAULT, статус надо читать независимо (стр.21).
4. Новый DRDY не доказывает отсутствие обрыва; без проверки SR температуру не передавать регулятору. Значения ниже0 или выше600°C не ограничивать программно до границы: показывать реальное показание и признак выхода за проектный диапазон. Ниже0°C — запрет пуска до определённой процедуры допустимого холодного запуска, не придуманное подтверждение обрыва. Показание600°C и выше — авария; это последняя цифровая граница, НЕ доказательство реального физического предела600°C.
5. Отдельный внешний контроль возраста последней принятой выборки:600мс, монотонное время. В норме более ранний deadline210мс обнаруживает несостоявшееся преобразование; контроль возраста страхует зависание цепочки публикации данных. Защитный управляющий цикл не должен зависеть от HTTP/UI. Системное зависание остаётся задачей watchdog, не устраняется одним таймером свежести.
6. При отказе любого обязательного термоканала запрещены новый розжиг и подача топлива; команда K2 выключить, K1 выключить, авария защёлкивается в автомате. Вентиляцию не отключать этой веткой без утверждённой последовательности продувки; конкретное время/скорость и условия охлаждения определяются общим контрактом процесса. Не считать команду K2 доказательством размыкания сварившихся контактов. Возврат связи/датчика не является новым разрешением пуска.

## Точность и реальный предел600°C

Разрешение0.0078125°C не точность. Предел коррекции линейности K −0.13…+0.12°C (стр.4) не является полной погрешностью канала. Холодный спай, входные погрешности, действительная термопара/удлинитель, термо-ЭДС переходов, температурный градиент клемма–ИС, помехи и старение остаются отдельными членами.

Примечание изготовителя о full-scale: https://ez.analog.com/data_converters/a/documents/DO12556/how-do-i-interpret-the-full-scale-error-of-the-max31856 прочитано. Не превращать ±0.15%FS в ±0.15% от600°C и не выдавать только линейзацию за точность изделия. Для численного общего предела требуется однозначная передаточная/ошибочная модель выбранного K-режима и характеристики конкретных зондов. Численный общий PASS здесь не назначен.

Условие выбора рабочей аварийной уставки:
 T_trip + E_under + v_max*(tau_probe + t_detect + tau_actuator) + delta_T_residual <= 600°C.
E_under — наибольшее занижение показания;v_max — обоснованная скорость роста температуры;tau_probe — запаздывание установленного зонда;t_detect — задержка измерения/решения;tau_actuator — выключение;delta_T_residual — остаточный рост от тепловой инерции. Для обрыва710мс — только предварительная оболочка t_detect, не универсальная задержка перегрева. Не подставлять неизвестные нулём и не назначать600°C рабочей уставкой. Нужны конкретные зонд/монтаж и тепловая характеристика; это ограничивает допуск горения, но не независимую подготовку CAD.

## Приёмочные сценарии будущей реализации

- Положительный: два канала одновременно, отдельныеCS/DRDY, период250мс; обслуживание<=10мс под HTTP нагрузкой, нет блокировки автомата.
- Обрыв любого провода, в том числе перед/после теста текущего цикла: SR OPEN, старая выборка не валидируется, обнаружение<=710мс при принятом интерфейсе.
- DRDY stuck HIGH и stuck LOW; SPI timeout; readback конфигурации неверен; сброс одногоMAX31856; старый статус; ошибка возникает между чтениямиSR; одинаковые последовательные температуры.
- Температура за0…600, отрицательные знаковые значения, CJ out-of-range,OVUV и их сочетания; ошибка не замазывается округлением/ограничением показания.
- Математические векторы сырого24bitTC:000000→0°C;000080→0.03125°C;190000→400°C;258000→600°C;FFFF80→−0.03125°C;FFE000→−2°C;FF0000→−16°C. Формула signed24/4096, младшие3бита TC зарезервированы; векторы вычислены инструментом, не исполнены в firmware.
- Сброс/потеря связи не восстанавливаютRUN; разрешение очистки аварии не равно командеSTART. Физических испытаний нет; этот список — критерий будущей приёмки, не пройденные тесты.
