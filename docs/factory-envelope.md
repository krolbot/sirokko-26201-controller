# Заводская подготовка параметров NVS

Для обычной настройки используйте веб-форму: **Настройки → Параметры отопителя**. Этот способ нужен для подготовки нового устройства до подключения к его сети.

## Подготовить исходные пределы

`SafetyEnvelope` задаёт допустимые температуры, длительности этапов и команды вентилятора. Регулятор изменяет команду двигателя в заданном рабочем диапазоне.

Из заводской инструкции для 262 перенесены предварительный накал 30 с и минимальное охлаждение 150 с. Допустимый накал — 30–60 с, предельное время розжига — не более 90 с. Остальные поля заполняются для конкретной установки; номинальная температура выхлопа 450 °C не является порогом перегрева. Источники и незаданные параметры перечислены в [таблице параметров](heater-sources.md).

Вход инструмента — JSON с двумя ключами:

- `qualification_reference`: непустая строка, позволяющая определить источник выбранных пределов;
- `envelope`: объект со всеми полями таблицы ниже. Значения — целые числа. Дополнительные поля не допускаются.

| Поле внутри `envelope` | Единица | Назначение |
|---|---|---|
| `preheat_ms` | мс | Предварительный нагрев свечой |
| `ignition_timeout_ms` | мс | Предельное ожидание подтверждения розжига после включения двигателя и муфты |
| `postpurge_ms` | мс | Минимальное время охлаждения после остановки и обрыва питания |
| `cooling_exhaust_milli_c` | тысячные °C | Выключение вентилятора при выхлопе строго ниже этого значения; начальное 40000 выбрано владельцем |
| `maximum_exhaust_milli_c` | тысячные °C | Верхний предел температуры выхлопа |
| `minimum_run_exhaust_milli_c` | тысячные °C | Единый порог выхлопа для окончания розжига и обнаружения погасания |
| `purge_speed_code` | код ШИМ | Команда вентилятора при продувке |
| `maximum_speed_code` | код ШИМ | Верхняя рабочая команда; также используется при розжиге |
| `minimum_speed_code` | код ШИМ | Нижняя рабочая команда; не выше максимальной |

Поля `*_speed_code` и `minimum_speed_code` задаются в кодах ШИМ. Допустимость и взаимные ограничения полей проверяет `valid_safety_envelope()` в [profile.cpp](../firmware/components/control_core/profile.cpp). Определение кодов находится в [control.hpp](../firmware/components/control_core/include/sirokko/control.hpp).

Сохраните заполненный JSON вне репозитория. В окружении ESP-IDF 5.2.3 с доступным `g++`, **из корня репозитория**:

```sh
python3 firmware/tools/prepare_factory_envelope.py \
  --input /path/to/heater-envelope.json \
  --output-dir /path/to/new-envelope-output
```

Выходной каталог должен быть новым. Инструмент создаёт `envelope_v6.bin`, `envelope.csv` и `manifest.json`, проверяет структуру и кодирует данные компилятором ESP32-S3.

## Записать параметры нового устройства

Этот способ предназначен **только для первоначального заполнения NVS**. Перезапись NVS уже настроенного устройства удалит настройки и пароль Wi-Fi. Не используйте этот шаг для обычного обновления прошивки.

Из созданного выходного каталога:

```sh
python3 "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" \
  generate envelope.csv nvs.bin 0x6000
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash 0x9000 nvs.bin
```

Раздел `nvs`: адрес `0x9000`, размер `0x6000`, согласно [partitions.csv](../firmware/partitions.csv).
