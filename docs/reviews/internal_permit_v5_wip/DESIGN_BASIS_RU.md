# Sirokko V5 — минимальная защита без внешнего J25

DRAFT / NOT FOR ORDER / NO POWER / NO FIRE

## Инженерное решение
Температурный контроль двух термопар выполняет ESP32. Внешняя термозащита и её питание J25 исключены. Для минимального аппаратного разрешения используется уже существующий MCU_PERMIT; отдельного внешнего THERMAL_OK больше нет.

Неиспользуемый после удаления интерфейса вход U6.2 присоединён к соседнему U6.1 WD_OK. Это не постоянная единица: WD_OK снимается аппаратным watchdog. Тождество A AND A = A сохраняет требуемую функцию без дополнительной микросхемы. Удалён ставший ненужным резистор R701, его схема и footprint. Добавлена одна F.Cu дорожка U6.1–U6.2: 1,27 мм, ширина 0,25 мм, без переходов. Остальные медные объекты сохранены.

CLEAR_N = WD_OK AND RELAY_DRIVER_OK AND RESET_RELEASED AND P24_PRESENT AND MCU_PERMIT.
При CLEAR_N=0 защёлка запрещает работу. Для разрешения нужен новый положительный фронт ARM; возврат условия сам по себе не разрешает повторный пуск. GLOW_CMD и FUEL_CMD остаются независимыми.

## Обязательный контракт будущей новой прошивки
MCU_PERMIT по умолчанию LOW; не взводить его при запуске, загрузке, reset или отсутствии валидной самопроверки. Разрешать только после свежих валидных показаний обеих термопар, проверок допустимых температур и остальных условий процесса. При обрыве/ошибке/устаревших данных или превышении температур снять разрешение и выполнить предусмотренный безопасный останов. Пороговые температуры, сроки свежести и поведение продувки надо окончательно квалифицировать по отопителю; эта булева проверка их не назначает.
Heartbeat должен подтверждать успешную итерацию самого цикла управления, а не жить независимо в таймере или сетевой задаче. При потере управляющего цикла аппаратный watchdog снимает разрешение. Накал и топливо запрещаются, но их отключение не должно блокировать необходимую продувку исправным двигательным каналом.
Новая прошивка ещё НЕ реализована. Старая прошивка НЕ совместима с этой приёмкой и не должна использоваться для включения платы.

## Честная граница защиты
Независимого аппаратного температурного ограничителя в этом решении нет. Если ошибочная прошивка одновременно сохраняет MCU_PERMIT и heartbeat, один watchdog не гарантирует останов по перегреву. Булева модель явно содержит такой отрицательный пример. Данный выбор следует требованию основной программной защиты; это не подтверждение безопасности горелки или соответствия неизвестному стандарту. Огневой допуск не выдаётся.
Таймаут watchdog, динамика сброса/питания, зазоры уровней и нагрев требуют отдельной приёмки. Статическая формула не подтверждает переходные процессы.

## Проверено
Полный корневой XML: удалены R701.1/R701.2; единственное переназначение — U6.2 с бывшего THERMAL_OK на WD_OK. Остальные контакты и сети точны. J25 отсутствует, J12 VDD/DQ/GND сохранён.
Native reopen: 1716 прежних tracks/vias точны по UUID, геометрии, слоям, ширине и сети. Добавлен один track, ноль via; среди остальных физических PAD-пар 0 потерь, 1 ожидаемое добавление U6.1↔U6.2. Отрицательный контроль без этой дорожки выявляет обрыв пары даже при одинаковом присвоенном имени сети.
Проверены 4096 булевых сочетаний входов, состояния защёлки и ARM. Это не тест реального времени и не проверка новой прошивки.
ERC exit0, 0 ошибок / 0 предупреждений. DRC exit5: 117 unconnected, 81 track_dangling + 5 via_dangling, 0 parity. Полное мультимножество 86 предупреждений совпадает с V4; ухудшений не скрывали. Снижение 119→117 частично связано с удалением резистора и не означает завершения платы.

## Состояние
Компоновка/общая разводка/силовые режимы не завершены. Питание, производство и огневые испытания запрещены. Прошивка не менялась, новая реализация только после окончания платы. Готовые DevKit/TFT и внешние подключения V4 не менялись.
