## Первоначальная настройка

### 1. Записать готовую прошивку

Скачайте `Sirokko-firmware.zip` из [последнего выпуска](https://github.com/krolbot/sirokko-26201-controller/releases/latest). Распакуйте его целиком, сохранив подкаталоги. Это комплект для USB-записи, а не файл для веб-обновления.

**Выньте DevKit из обесточенной платы Sirokko** и подключите его к USB. В окружении ESP-IDF 5.2.3 перейдите в каталог распакованного комплекта:

```sh
sha256sum -c SHA256SUMS
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash @flash_args
```

Замените `/dev/ttyACM0` фактическим портом; в Windows это может быть `COM5`. Адреса и параметры образов уже находятся в `flash_args`: не переносите их из чужой инструкции. Если плата не входит в загрузчик автоматически, используйте BOOT/EN согласно документации YD-ESP32-S3.

USB-запись приложения не создаёт настройки конкретного отопителя. На новом устройстве без них запуск нагрева и калибровки заблокирован.

### 2. Подготовить исходные пределы

Исходные пределы описывают допустимые температуры, длительности этапов и команды вентилятора конкретного отопителя. Прошивка называет эту запись `SafetyEnvelope`. Калибровка определяет рабочий режим **внутри** этих пределов, а не заменяет их.

Готового универсального набора чисел в проекте нет. Значения должны быть определены для используемого отопителя, датчиков и привода. Нельзя брать максимумы программного валидатора как рекомендуемые рабочие значения.

Вход инструмента — JSON с двумя ключами:

- `qualification_reference`: непустая строка, позволяющая определить источник выбранных пределов;
- `envelope`: объект со всеми полями таблицы ниже. Значения — целые числа; никаких дополнительных полей или `provisioned` добавлять не нужно.

| Поле внутри `envelope` | Единица | Назначение |
|---|---|---|
| `recovery_purge_ms` | мс | Восстановительная продувка |
| `prepurge_ms` | мс | Продувка перед розжигом |
| `preheat_ms` | мс | Предварительный нагрев свечой |
| `ignition_ms` | мс | Этап розжига |
| `verify_ms` | мс | Подтверждение горения |
| `postpurge_ms` | мс | Продувка после остановки |
| `maximum_purge_exit_exhaust_milli_c` | тысячные °C | Порог температуры выхлопа для завершения продувки |
| `maximum_purge_exit_air_milli_c` | тысячные °C | Порог температуры горячего воздуха для завершения продувки |
| `maximum_exhaust_milli_c` | тысячные °C | Верхний предел температуры выхлопа |
| `maximum_air_milli_c` | тысячные °C | Верхний предел температуры горячего воздуха |
| `minimum_ignition_rise_milli_c` | тысячные °C | Минимальный рост температуры выхлопа при розжиге |
| `minimum_run_exhaust_milli_c` | тысячные °C | Нижний температурный порог выхлопа при работе |
| `minimum_ignition_air_rise_milli_c` | тысячные °C | Минимальный рост температуры горячего воздуха при розжиге |
| `purge_speed_code` | код ШИМ | Команда вентилятора при продувке |
| `reference_speed_code` | код ШИМ | Опорная команда для калибровки |
| `exploration_floor_code` | код ШИМ | Нижняя граница исследования при калибровке; для калибровки нужна ненулевая граница ниже опорной команды |

Поля `*_speed_code` и `exploration_floor_code` — внутренние коды, не проценты на экране. Допустимость и взаимные ограничения полей проверяет `valid_safety_envelope()` в [profile.cpp](../firmware/components/control_core/profile.cpp). Определение кодов находится в [control.hpp](../firmware/components/control_core/include/sirokko/control.hpp).

Сохраните заполненный JSON вне репозитория. В окружении ESP-IDF 5.2.3 с доступным `g++`, **из корня репозитория**:

```sh
python3 firmware/tools/prepare_factory_envelope.py \
  --input /path/to/heater-envelope.json \
  --output-dir /path/to/new-envelope-output
```

Выходной каталог должен быть новым. Инструмент создаёт `envelope_v1.bin`, `envelope.csv` и `manifest.json`, проверяет структуру и кодирует данные компилятором ESP32-S3. Он не определяет физическую пригодность введённых значений и ничего не записывает в устройство.

### 3. Записать параметры нового устройства

Этот способ предназначен **только для первоначального заполнения NVS**. Перезапись NVS уже настроенного устройства удалит сохранённую модель, настройки и пароль Wi-Fi. Не используйте этот шаг для обычного обновления прошивки.

Из созданного выходного каталога:

```sh
python3 "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" \
  generate envelope.csv nvs.bin 0x6000
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash 0x9000 nvs.bin
```

DevKit всё ещё должен быть вынут из основной платы. Адрес `0x9000` и размер `0x6000` соответствуют разделу `nvs` в [partitions.csv](../firmware/partitions.csv) этого проекта. Для изменённой таблицы разделов эти значения нельзя переносить автоматически. Полное стирание flash для этой операции не требуется.

### 4. Установить контроллер и выполнить калибровку

Отключите USB, установите DevKit в обесточенную плату и завершите подключения по [инструкции сборки](assembly.md). После подачи питания проверьте в **Диагностике** показания обоих MAX31856 и комнатного датчика.

Запустите **Калибровку** на местной панели либо **Ввод в эксплуатацию** в веб-интерфейсе. Калибровка включает реальные исполнительные устройства. При отсутствии или неустойчивом горении KEY0 останавливает процесс. Дождитесь успешного завершения и сохранения модели; только после этого используйте обычный пуск.

Если запуск недоступен, проверьте сообщение о причине: исходные пределы, датчики, температура, модель или хранение данных. Не подменяйте настройку снятием программной блокировки.

## Управление

### Местная панель

На панели находятся экран, энкодер с нажатием и отдельная кнопка **KEY0 — Пуск/стоп**.

- **Нажать KEY0:** запустить готовый к работе отопитель; при запуске или нагреве — остановить. Это обычное нажатие, не удержание. После одного срабатывания отпустите кнопку перед следующим.
- **Повернуть энкодер на главном экране:** изменить уровень в ручном режиме или заданную температуру в температурном.
- **Один раз нажать энкодер:** открыть меню, выбрать пункт или сохранить редактируемое значение.
- **Дважды нажать энкодер:** отменить редактирование или вернуться назад. Из меню — на главный экран; из диагностики, Wi-Fi и обновления — в меню.

Во время подтверждения команды, аварии или недоступных данных некоторые действия заблокированы. Сообщение на экране объясняет текущее состояние; повторное нажатие не устраняет причину блокировки.

### Режим и таймер

В пункте **Режим** выбирается ручное управление уровнем или поддержание температуры помещения. В температурном режиме нужен исправный комнатный DS18B20. Ручной уровень задаёт команду управления, а не измеренные обороты двигателя.

**Таймер** ограничивает продолжительность нагрева. Если отопитель остановлен, сохранённая длительность начнёт отсчёт после ручного пуска. Во время работы новый таймер отсчитывается от текущего момента. Нулевое значение отключает таймер. Окончание времени вызывает штатную остановку с продувкой, а не немедленное отключение питания.

### Управление с телефона

1. Откройте на панели пункт **Wi-Fi** и прочитайте имя сети и индивидуальный пароль.
2. Подключите телефон к этой сети. Доступа в Интернет через неё может не быть — оставайтесь подключённым к контроллеру.
3. Откройте `http://192.168.4.1` и введите пароль точки доступа в веб-интерфейсе.

Нижняя навигация содержит **Главную**, **Таймер** и **Настройки**. В настройках доступны показания и журнал, ввод в эксплуатацию, плавность регулирования и обновление прошивки. Команды выполняются контроллером; закрытие страницы не является командой остановки.

### Остановка и ошибки

Остановите нагрев кнопкой KEY0 либо кнопкой **Остановить** в веб-интерфейсе. Дайте контроллеру закончить охлаждающую продувку; не заменяйте штатную остановку отключением питания.

При ошибке прочитайте сообщение и показания в **Диагностике**. После устранения причины запрос сброса ошибки доступен нажатием энкодера на главном экране; контроллер всё равно проверяет возможность сброса. Перезапуск ESP32 кнопкой EN — не то же самое, что штатная остановка или сброс причины аварии.

### Калибровка

Калибровка доступна только после задания исходных пределов конкретного отопителя и при выполнении условий запуска. Она управляет реальным нагревом и по двум термопарам определяет рабочую модель; это не демонстрационный режим.

Запуск — пункт **Калибровка** на панели или **Ввод в эксплуатацию** в веб-интерфейсе. Во время калибровки KEY0 останавливает процесс и отмечает проблему горения. Полученная модель используется только после успешного сохранения.

Отсутствующие исходные пределы, ошибки датчиков и неисправность хранения не исправляются запуском калибровки. До неё выполните [начальную настройку](user-guide.md#первоначальная-настройка).

### Обновление

Веб-интерфейс принимает подписанный файл `.sota`, а не ZIP-архив или обычный `.bin`. Обновление выполняется после остановки и охлаждения. После перезагрузки проверьте отображаемую версию. Первую запись и восстановление выполняют через USB на вынутом из основной платы DevKit.

Пакет `.sota` должен быть подписан ключом, соответствующим открытому ключу установленной прошивки. USB-комплект из Releases не является OTA-пакетом. [Сборка и подпись собственного пакета](../firmware/README.md#подпись-ota). При обычном обновлении приложения NVS заново не записывается.
