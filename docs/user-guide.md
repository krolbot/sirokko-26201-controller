## Первоначальная настройка

### 1. Записать готовую прошивку

Скачайте `Sirokko-firmware.zip` из [последнего выпуска](https://github.com/krolbot/sirokko-26201-controller/releases/latest). Распакуйте его целиком, сохранив подкаталоги.

**Выньте DevKit из обесточенной платы Sirokko** и подключите его к USB. В окружении ESP-IDF 5.2.3 перейдите в каталог распакованного комплекта:

```sh
sha256sum -c SHA256SUMS
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash @flash_args
```

Замените `/dev/ttyACM0` фактическим портом; в Windows это может быть `COM5`. Адреса записи заданы в `flash_args`. Если плата не входит в загрузчик автоматически, используйте BOOT/EN согласно документации YD-ESP32-S3.

До первоначальной настройки нагрев и калибровка заблокированы.

### 2. Подготовить исходные пределы

`SafetyEnvelope` задаёт допустимые температуры, длительности этапов и команды вентилятора. Калибровка подбирает рабочий режим в этих пределах.

Готового набора параметров нет: значения необходимо определить для используемого отопителя, датчиков и привода. Границы программного валидатора не являются рабочими настройками.

Вход инструмента — JSON с двумя ключами:

- `qualification_reference`: непустая строка, позволяющая определить источник выбранных пределов;
- `envelope`: объект со всеми полями таблицы ниже. Значения — целые числа. Дополнительные поля не допускаются.

| Поле внутри `envelope` | Единица | Назначение |
|---|---|---|
| `recovery_purge_ms` | мс | Восстановительная продувка |
| `prepurge_ms` | мс | Продувка перед розжигом |
| `preheat_ms` | мс | Предварительный нагрев свечой |
| `ignition_ms` | мс | Этап розжига |
| `verify_ms` | мс | Подтверждение горения |
| `postpurge_ms` | мс | Продувка после остановки |
| `maximum_purge_exit_exhaust_milli_c` | тысячные °C | Порог температуры выхлопа для завершения продувки |
| `maximum_purge_exit_air_milli_c` | тысячные °C | Порог температуры горячего воздуха для завершения продувки |
| `maximum_exhaust_milli_c` | тысячные °C | Верхний предел температуры выхлопа |
| `maximum_air_milli_c` | тысячные °C | Верхний предел температуры горячего воздуха |
| `minimum_ignition_rise_milli_c` | тысячные °C | Минимальный рост температуры выхлопа при розжиге |
| `minimum_run_exhaust_milli_c` | тысячные °C | Нижний температурный порог выхлопа при работе |
| `minimum_ignition_air_rise_milli_c` | тысячные °C | Минимальный рост температуры горячего воздуха при розжиге |
| `purge_speed_code` | код ШИМ | Команда вентилятора при продувке |
| `reference_speed_code` | код ШИМ | Опорная команда для калибровки |
| `exploration_floor_code` | код ШИМ | Нижняя граница исследования при калибровке; для калибровки нужна ненулевая граница ниже опорной команды |

Поля `*_speed_code` и `exploration_floor_code` задаются в кодах ШИМ. Допустимость и взаимные ограничения полей проверяет `valid_safety_envelope()` в [profile.cpp](../firmware/components/control_core/profile.cpp). Определение кодов находится в [control.hpp](../firmware/components/control_core/include/sirokko/control.hpp).

Сохраните заполненный JSON вне репозитория. В окружении ESP-IDF 5.2.3 с доступным `g++`, **из корня репозитория**:

```sh
python3 firmware/tools/prepare_factory_envelope.py \
  --input /path/to/heater-envelope.json \
  --output-dir /path/to/new-envelope-output
```

Выходной каталог должен быть новым. Инструмент создаёт `envelope_v1.bin`, `envelope.csv` и `manifest.json`, проверяет структуру и кодирует данные компилятором ESP32-S3.

### 3. Записать параметры нового устройства

Этот способ предназначен **только для первоначального заполнения NVS**. Перезапись NVS уже настроенного устройства удалит сохранённую модель, настройки и пароль Wi-Fi. Не используйте этот шаг для обычного обновления прошивки.

Из созданного выходного каталога:

```sh
python3 "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" \
  generate envelope.csv nvs.bin 0x6000
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash 0x9000 nvs.bin
```

Раздел `nvs`: адрес `0x9000`, размер `0x6000`, согласно [partitions.csv](../firmware/partitions.csv).

### 4. Установить контроллер и выполнить калибровку

Отключите USB, установите DevKit в обесточенную плату и завершите подключения по [инструкции сборки](assembly.md). После подачи питания проверьте в **Диагностике** показания обоих MAX31856 и комнатного датчика.

Запустите **Калибровку** на местной панели либо **Ввод в эксплуатацию** в веб-интерфейсе. При отсутствии или неустойчивом горении остановите калибровку кнопкой KEY0. Дождитесь успешного завершения и сохранения модели; только после этого используйте обычный пуск.

Если запуск недоступен, проверьте сообщение о причине: исходные пределы, датчики, температура, модель или хранение данных.

## Управление

### Местная панель

На панели находятся экран, энкодер с нажатием и отдельная кнопка **KEY0 — Пуск/стоп**.

- **Короткое нажатие KEY0:** пуск или остановка отопителя.
- **Повернуть энкодер на главном экране:** изменить уровень в ручном режиме или заданную температуру в температурном.
- **Один раз нажать энкодер:** открыть меню, выбрать пункт или сохранить редактируемое значение.
- **Дважды нажать энкодер:** отменить редактирование или вернуться назад. Из меню — на главный экран; из диагностики, Wi-Fi и обновления — в меню.

Причина блокировки управления отображается на экране.

### Режим и таймер

В пункте **Режим** выбирается ручное управление уровнем или поддержание температуры помещения. В температурном режиме используется комнатный DS18B20.

**Таймер** ограничивает продолжительность нагрева. Если отопитель остановлен, сохранённая длительность начнёт отсчёт после ручного пуска. Во время работы новый таймер отсчитывается от текущего момента. Нулевое значение отключает таймер. По окончании времени отопитель останавливается с продувкой.

### Управление с телефона

1. Подключите телефон к сети **Sirokko-XXXXXX**. Имя также показано на панели в пункте **Wi-Fi**. По умолчанию сеть открыта, пароль не требуется.
2. Доступа в Интернет через неё может не быть — оставайтесь подключённым к контроллеру.
3. После подключения телефон может предложить «Войти в сеть» и открыть страницу контроллера. Если окно не появилось, откройте `http://192.168.26.1` вручную: в открытом режиме веб-интерфейс сразу показывает состояние.

Чтобы включить защиту, откройте **Настройки → Wi-Fi и пароль**, дважды введите пароль и нажмите **Задать пароль**. Допускаются 8–63 латинских букв, цифр или символов без пробелов. Один пароль защищает сеть Wi-Fi и вход в браузере. Кнопка **Убрать пароль** возвращает открытый режим.

Настройка сохраняется в NVS и применяется после следующего включения питания; контроллер сам не перезагружается и не обрывает текущую связь. Перед отключением питания работающего отопителя завершите остановку и продувку. После включения с защитой переподключитесь к сети с новым паролем и введите его в браузере. На местной панели открытая сеть обозначается «Без пароля».

В открытом режиме любой находящийся рядом может подключиться к сети и управлять веб-интерфейсом.

При обновлении с версии 1.0.0 старый автоматически созданный пароль перестаёт использоваться: сеть становится открытой. Новый явно заданный пользователем пароль хранится отдельно (`wifi_password`) и сохраняется при следующих обновлениях; настройки отопителя не изменяются.

Нижняя навигация содержит **Главную**, **Таймер** и **Настройки**. В настройках доступны показания и журнал, ввод в эксплуатацию, плавность регулирования и обновление прошивки.

### Остановка и ошибки

Остановите нагрев кнопкой KEY0 либо кнопкой **Остановить** в веб-интерфейсе. Отключайте питание после завершения охлаждающей продувки.

При ошибке прочитайте сообщение и показания в **Диагностике**. После устранения причины нажмите энкодер на главном экране для сброса ошибки.

### Калибровка

Калибровка определяет рабочую модель отопителя по показаниям двух термопар во время нагрева.

Запуск — пункт **Калибровка** на панели или **Ввод в эксплуатацию** в веб-интерфейсе. Во время калибровки KEY0 останавливает процесс и отмечает проблему горения. Полученная модель используется только после успешного сохранения.

Перед калибровкой выполните [начальную настройку](user-guide.md#первоначальная-настройка).

### Обновление

В **Настройки → Обновление** загрузите подписанный файл `.sota`. Обновление выполняется после остановки и охлаждения. После перезагрузки проверьте отображаемую версию. Первую запись и восстановление выполняют через USB на вынутом из основной платы DevKit.

Пакет `.sota` должен быть подписан ключом, соответствующим открытому ключу установленной прошивки. [Сборка и подпись собственного пакета](../firmware/README.md#подпись-ota). При обычном обновлении приложения NVS заново не записывается.

Точка доступа не предоставляет Интернет. Для автоматического открытия контроллер выдаёт свой DNS через DHCP и перенаправляет HTTP-проверки подключения на главную страницу. HTTPS не перехватывается. Автоматическое окно зависит от ОС, VPN и настроек частного DNS. После обновления адреса переподключитесь к Wi-Fi, чтобы получить новые сетевые настройки.
